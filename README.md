# 한결물산 ERP

한결물산 내부 사용자가 브라우저에서 품목, 본사 재고, 지점 사내 발주를 처리하는 ERP입니다. 이 문서는 개발 API가 아니라 **화면을 직접 조작해 확인하는 방법**을 기준으로 작성되었습니다.

## 화면 테스트를 시작하기 전에

테스터는 처음 한 번만 아래 준비를 합니다. Neon PostgreSQL 연결 정보와 시드 비밀번호를 `.env.local`에 설정해야 합니다.

```bash
pnpm install
Copy-Item .env.example .env.local
pnpm db:migrate
pnpm db:seed
pnpm dev
```

브라우저에서 `http://localhost:3000`을 엽니다. 로그인 전에는 자동으로 로그인 화면으로 이동합니다.

모든 초기 계정의 비밀번호는 `.env.local`의 `INITIAL_ACCOUNT_PASSWORD` 값입니다.

| 테스트 역할 | 로그인 ID | 사용할 화면 |
|---|---|---|
| 관리자 | `admin1` | 품목 등록·수정, 엑셀 이관, 사내 발주 승인·반려·승인 취소 |
| 창고 | `wh1` | 사내 발주 출고 완료 |
| 강남지점 | `gn1` | 사내 발주 요청·미결 수량 취소·반려 건 재기안 |

화면 오른쪽 위의 **로그아웃**으로 역할을 바꿔가며 테스트합니다.

## 화면별 수동 테스트

### 1. 로그인과 대시보드

1. `/login`에서 `admin1`과 시드 비밀번호로 로그인합니다.
2. 루트(`/`)의 대시보드에 **품목 관리**, **사내 발주** 카드가 보여야 합니다.
3. 상단 메뉴 또는 카드로 각 화면에 이동합니다.
4. 로그아웃한 뒤 `gn1`으로 다시 로그인합니다. 대시보드에는 같은 진입 카드가 보이지만, 화면의 버튼과 데이터 열은 지점 권한에 맞춰 달라집니다.

### 2. 엑셀로 테스트용 품목·초기 재고 만들기

관리자로 로그인한 뒤 `/items`에서 **엑셀 이관**을 선택합니다. 첫 행을 아래 필드명으로 둔 `.xlsx` 파일을 업로드합니다. 영문 필드명 또는 괄호 안의 한국어 표기를 사용할 수 있습니다.

| 필드명 | 한국어 표기 | 예시 | 필수 |
|---|---|---|---|
| `itemCode` | 자체 품목코드 | `1001` | O |
| `itemName` | 상품명 | `테스트 세제` | O |
| `specRaw` | 규격 | `500ml 12입/박스` | |
| `purchasePrice` | 매입단가 | `10000` | O |
| `supplyPrice` | 지점 공급단가 | `12000` | O |
| `openingQty` | 초기 재고 | `100` | |
| `barcode`, `categoryMajor`, `categoryMinor`, `minStockQty`, `remarks` | 각 한글 표기 | 선택값 | |

업로드 성공 시 생성 건수와 규격 파싱 실패 건수가 표시됩니다. 위 예시는 품목 1건과 실재고 100박스를 만듭니다. 같은 품목코드, 빈 필수 값, 숫자가 아닌 금액·수량이 있는 파일은 어떤 행도 저장하지 않고 행 번호와 오류를 화면에 표시합니다.

### 3. 품목 관리와 권한별 표시

1. 관리자로 `/items`에 가서 **품목 등록**을 선택합니다.
2. 상품명, 포장 단위, 매입단가, 지점 공급단가를 입력해 저장합니다. 자체 품목코드는 입력하지 않으며 저장 뒤 자동 부여됩니다.
3. 목록의 상품명을 눌러 수정 화면으로 들어갑니다. 자체 품목코드는 수정할 수 없습니다.
4. `wh1`으로 다시 로그인해 같은 화면을 확인합니다. **매입단가** 열과 등록 버튼이 보이지 않아야 합니다.
5. `gn1`으로 다시 로그인해 확인합니다. **매입단가**, **실재고**, **출고 대기**, **최소 재고 수량** 열이 없어야 하며, 가용 수량은 **재고**로만 표시됩니다.

### 4. 지점 요청 → 관리자 승인 → 창고 출고

앞 절의 엑셀 파일에서 초기 재고 100을 등록한 뒤 다음 흐름을 테스트합니다.

1. `gn1`으로 로그인해 `/internal-orders`에서 **사내 발주 요청**을 선택합니다.
2. 이관한 품목을 고르고 요청 수량 `10`, 납기 요망일을 입력해 요청합니다. 재고가 부족하더라도 요청 자체는 `승인 대기`로 생성됩니다.
3. `admin1`으로 로그인해 해당 발주 상세를 열고 승인 수량 `10`과 출고 예정일을 입력해 **승인**합니다.
4. 관리자의 `/items` 목록에서 해당 품목이 `실재고 100 / 출고 대기 10 / 가용 재고 90`으로 보이는지 확인합니다. 지점 화면에는 `재고 90`만 보여야 합니다.
5. `wh1`으로 로그인해 발주 상세의 승인 이력에서 **출고 완료**를 누릅니다.
6. 관리자의 품목 목록에서 `실재고 90 / 출고 대기 0 / 가용 재고 90`인지 확인합니다. 출고 수량을 별도로 입력하는 화면은 없습니다. 승인 수량 전량만 출고됩니다.

### 5. 예외 흐름 확인

- 관리자는 `승인 대기` 발주에서 **반려**를 누를 수 있으며, 반려 사유를 비우면 저장되지 않습니다. 지점은 반려 건에서 **반려 건 복사하여 재기안**을 선택해 새 요청을 만듭니다.
- 일부만 승인한 발주의 남은 수량은 지점 사용자가 **미결 수량 취소**로 취소할 수 있습니다. 이미 승인된 수량은 취소할 수 없습니다.
- 관리자는 출고 전 승인 건의 **승인 취소**를 할 수 있습니다. 출고 완료된 승인에는 취소 버튼이 없고, 서버도 취소를 거부합니다.
- 창고 외 역할에는 출고 완료 버튼이 보이지 않습니다. 서버 권한도 별도로 검증하므로 주소를 직접 호출해도 출고되지 않습니다.

## 현재 화면 범위

- 로그인, 루트 대시보드, 로그아웃
- 품목 목록·등록·수정·엑셀 초기 이관
- 역할별 사내 발주 요청·조회·승인·반려·취소·출고

거래처, 외부 발주, 입고, 재고 조정, 지점 재고, 리포트의 전용 화면은 다음 구현 단계 대상입니다.

## 기술 정보

Next.js App Router, Tailwind CSS, Auth.js, Neon PostgreSQL, Drizzle ORM, Zod, TanStack Table, SheetJS를 사용합니다. 재고는 `items` 테이블에 저장하지 않고 append-only `inventory_ledger`의 합계를 `v_item_stock` 뷰에서 읽습니다. 승인·출고는 트랜잭션 단위 advisory lock으로 동일 품목을 직렬화합니다.
