# 작업 분할 (tasks.md)

㈜한결물산 사내 ERP 웹시스템

---

## 0. 이 문서의 사용법

### 0.1 목적

-Codex에게 한 번에 넘길 작업 단위를 정의합니다. **한 티켓 = 한 세션**이 원칙입니다. 티켓이 커지면 에이전트가 명세를 잊고 추론으로 채우기 시작합니다.-
위 원칙은 무시한다. 시간이 부족하기 때문에, 단계별 구현을 한번에 하도록 한다.

### 0.2 티켓 서식

```
### T-NN · 제목
- 선행: 완료되어야 할 티켓
- 참조: 읽어야 할 문서와 절
- 규칙: 적용할 BR-ID
- 산출: 만들 파일
- 완료 조건: 통과해야 할 AT-ID 또는 검증 방법
- 금지: 이 티켓에서 손대면 안 되는 것
```

### 0.3 Codex 프롬프트 템플릿

티켓을 넘길 때 아래 형식을 쓰십시오.

```
T-07을 진행한다.

먼저 AGENTS.md, docs/business-rules.md의 IOR 절, docs/state-machine.md 1~2장,
docs/api-spec.md 2.4를 읽어라.

읽은 뒤 변경할 파일 목록과 적용할 BR-ID를 먼저 제시하고 멈춰라.
내가 동의하면 그때 코드를 써라.

tasks.md의 T-07 금지 항목을 지켜라.
```

**계획을 먼저 받고 동의한 뒤 코드를 쓰게 하십시오.** 이 절차를 생략하면 범위 밖 파일이 함께 수정됩니다.

### 0.4 진행 원칙

- 티켓 순서를 건너뛰지 않는다. 선행이 끝나야 다음으로 간다
- `[병렬]` 표시가 있는 티켓끼리는 동시에 진행해도 된다
- 한 세션에서 여러 티켓을 처리하지 않는다
- 티켓 완료 시 완료 조건의 테스트를 실행하고 결과를 확인한다

## 7. 우선순위

일정이 밀릴 경우의 절단선입니다.

**절대 못 빼는 것 (T-01 ~ T-17)**
기반, 마스터, 재고 원장, 일괄 업로드, 사내 발주 전 과정. 여기까지가 고객의 핵심 페인포인트(재고 불일치, 발주 누락)를 해결합니다.

**빼면 시스템이 반쪽 (T-18 ~ T-22)**
외부 발주와 입고가 없으면 재고가 늘어날 방법이 없습니다. T-20 재고 조정은 T-18보다 우선입니다.

**마지막에 조정 가능 (T-23 ~ T-24)**
지점 재고는 수기 입력이라 최악의 경우 엑셀 병행이 가능합니다. 리포트도 조회 화면으로 임시 대체가 됩니다. 다만 둘 다 Must have이므로 고객 동의 없이 빼지 마십시오.
