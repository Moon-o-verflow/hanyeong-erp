# 권한 정의 (permissions.md)

㈜한결물산 사내 ERP 웹시스템

---

## 0. 이 문서의 사용법

### 0.1 단일 진실 원천 범위

**누가 무엇을 할 수 있는가**의 유일한 원천입니다. 액션 허용 여부, 데이터 범위(행 수준), 필드 노출 범위(열 수준)를 모두 담습니다.

업무 규칙은 `business-rules.md`, 엔드포인트 정의는 `api-spec.md`를 따릅니다.

### 0.2 에이전트 준수 사항

1. 이 문서에 `O`로 표시되지 않은 조합은 **거부**한다. 명시되지 않은 것은 허용이 아니라 금지다.
2. 권한 검증은 서버에서 수행한다. 화면 숨김은 편의일 뿐 보안 수단이 아니다.
3. 행 범위 제한(2장)과 필드 마스킹(3장)은 **API 응답 생성 이전**에 적용한다.
4. 권한 검증 로직을 엔드포인트마다 흩뿌리지 말고 공통 계층에 둔다.

## 1. 권한 종류

| 값 | 한국어 | 인원 | 소속 |
|---|---|---|---|
| `ADMIN` | 관리자 | 3 | 본사 |
| `PURCHASER` | 구매 | 본사 (겸직 가능) | 본사 |
| `WAREHOUSE` | 창고 | 4 | 본사 창고 |
| `BRANCH` | 지점 | 10 | 5개 지점, 각 2명 |

사용자는 **하나의 권한만** 갖습니다 (BR-AUT-001). 복수 권한이 필요한 상황이 발생하면 임의로 처리하지 말고 보고하십시오.

`BRANCH` 사용자는 반드시 `branch_id`를 가지며, 그 외 권한은 `branch_id`가 없습니다.

## 3. 필드 마스킹

권한에 따라 응답에서 **제외**해야 하는 필드입니다. `null`로 채우지 말고 키 자체를 제거하십시오.

| 필드 | ADMIN | PURCHASER | WAREHOUSE | BRANCH | 근거 |
|---|---|---|---|---|---|
| `onHandQty` (실재고) | O | O | O | **제외** | BR-INV-012 |
| `allocatedQty` (할당) | O | O | O | **제외** | BR-INV-012 |
| `availableQty` (가용) | O | O | O | O | |
| `purchasePrice` (매입단가) | O | O | **제외** | **제외** | BR-AUT-003 |
| `supplyPrice` (지점 공급단가) | O | O | O | O | |
| `minStockQty` | O | O | O | **제외** | 본사 운영 지표 |

**창고 권한에서 매입단가를 제외한 이유**: 입고·출고 처리에 단가가 필요하지 않습니다. 최소 권한 원칙에 따릅니다. 이는 [제안]이며 실무상 필요하다면 조정 가능합니다.

`availableQty`는 모든 권한에 노출되지만, 지점 화면에서의 표기는 "재고"이고 본사 화면에서는 "가용 재고"입니다 (`glossary.md` 6장).

## 4. 행 범위 제한

`BRANCH` 권한 사용자의 조회·수정 대상은 자기 지점으로 한정됩니다. 서버가 **강제로 조건을 주입**하며, 요청 파라미터로 다른 지점을 지정하면 거부합니다.

| 리소스 | 주입 조건 |
|---|---|
| `internal_orders` | `branch_id = session.branchId` |
| `internal_order_approvals` | 상위 발주의 `branch_id = session.branchId` |
| `branch_stocks` | `branch_id = session.branchId` |
| `shipments` | 상위 발주의 `branch_id = session.branchId` |

**구현 주의**: 필터 파라미터의 `branchId`를 그대로 쿼리에 넣는 방식은 위반입니다. `BRANCH` 세션에서는 파라미터를 무시하고 세션 값으로 덮어쓰십시오. 파라미터가 세션과 다르면 `E-AUTH-003`을 반환하는 것도 허용됩니다.

`ADMIN`, `PURCHASER`, `WAREHOUSE`에는 행 범위 제한이 없습니다.

## 5. 검증 순서

요청 처리 시 다음 순서로 검증합니다. 앞 단계가 실패하면 뒤를 수행하지 않습니다.

```
1. 인증          세션·토큰 유효성          → E-AUTH-001
2. 액션 권한      2장 매트릭스              → E-AUTH-002
3. 행 범위        4장 주입·검증             → E-AUTH-003
4. 상태 전이      state-machine.md          → E-IOR-001 등
5. 업무 규칙      business-rules.md         → E-INV-001 등
6. 처리 및 응답   3장 마스킹 적용
```

**2단계와 5단계를 섞지 마십시오.** "권한이 없어서" 실패한 것과 "재고가 부족해서" 실패한 것은 사용자에게 다르게 안내되어야 합니다.

## 6. 감사 기록

다음 액션은 수행자와 일시를 반드시 남깁니다. 해당 컬럼이 `data-model.md`에 정의되어 있습니다.

| 액션 | 기록 위치 |
|---|---|
| 사내 발주 승인 | `internal_order_approvals.approved_by` / `approved_at` |
| 승인 취소 | `internal_order_approvals.canceled_by` / `canceled_at` |
| 출고 완료 | `shipments.shipped_by` / `shipped_at` |
| 입고 완료 | `receipts.received_by` / `received_at` |
| 재고 조정 | `stock_adjustments.adjusted_by` / `adjusted_at` |
| 모든 재고 변동 | `inventory_ledger.created_by` / `created_at` |
| 지점 재고 입력 | `branch_stocks.updated_by` / `updated_at` |

재고 원장은 append-only이므로 그 자체가 감사 로그 역할을 합니다. 별도의 감사 테이블을 만들지 마십시오.

## 7. 초기 계정

시드 데이터로 생성할 계정입니다. 실제 운영 계정 발급 절차는 미정입니다 (BR-AUT-005).

| 용도 | 권한 | 수 |
|---|---|---|
| 본사 관리자 | `ADMIN` | 3 |
| 창고 담당 | `WAREHOUSE` | 4 |
| 지점 담당 | `BRANCH` | 10 (지점당 2명) |

`PURCHASER` 계정은 초기 시드에 포함하지 않습니다. 외부 발주가 관리자 권한으로도 가능하므로(2.4장), 실제 겸직 구조가 확인된 뒤 부여합니다.
